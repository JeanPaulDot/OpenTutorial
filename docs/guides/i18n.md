# Internationalization

## Two ways to write text

Anywhere a spec accepts text, you may write a string or a key:

```jsonc
{ "title": "Welcome" }
{ "title": { "key": "tour.welcome.title", "fallback": "Welcome" } }
```

Keys are resolved through a resolver you supply. If the resolver returns
nothing, the `fallback` is used; if there is no fallback, the key itself is
shown — visible, so a missing translation is obvious in review rather than
producing a blank popover.

## Resolvers

### Flat map

```ts
import { createKeyResolver } from '@opentutorial/core';

createTutorialLayer({
  specs,
  locale: 'fr',
  i18nResolver: createKeyResolver({
    'tour.welcome.title': 'Bienvenue',
    'tour.welcome.body': 'Cliquez sur **Suivant** pour continuer.',
  }),
});
```

### Per-locale maps

```ts
import { createLocaleResolver } from '@opentutorial/core';

const resolver = createLocaleResolver({
  en: { 'tour.welcome.title': 'Welcome' },
  fr: { 'tour.welcome.title': 'Bienvenue' },
  'fr-CA': { 'tour.welcome.title': 'Bienvenue' },
}, 'en');
```

Lookup falls back `fr-CA` → `fr` → default locale.

### Your own i18n library

The resolver is just `(key, locale) => string | undefined`, so anything works:

```ts
i18nResolver: (key) => i18next.t(key)
i18nResolver: (key) => intl.formatMessage({ id: key })
i18nResolver: (key, locale) => myCatalog[locale]?.[key]
```

## Switching locale at runtime

```ts
layer.setLocale('de');
```

A running tour re-renders in place — no restart, no lost progress.

## Interpolation

`{{name}}` placeholders are filled from the tour context:

```ts
createTutorialLayer({ specs, context: { name: 'Ada', seats: 5 } });
```

```jsonc
{ "content": "Welcome back, {{name}}. You have {{seats}} seats." }
```

Dotted paths work: `{{user.plan}}`, `{{org.billing.tier}}`.

An unresolved placeholder is left **verbatim** rather than blanked, so
`Welcome, {{name}}` in the UI tells you the context key is missing — much easier
to spot than `Welcome, `.

Numbers are formatted for the active locale: `{{seats}}` with `1234567` renders
`1,234,567` in `en` and `1.234.567` in `de`.

## Pluralization

A small subset of ICU MessageFormat:

```jsonc
{ "content": "You have {{count, plural, one {# tour} other {# tours}}} left." }
```

`#` is replaced with the locale-formatted count.

Category selection uses `Intl.PluralRules`, so every CLDR category works —
including Slavic `few`/`many` and Arabic `zero`/`two`:

```ts
createKeyResolver({
  'checklist.remaining':
    '{{n, plural, one {# krok} few {# kroki} many {# kroków} other {# kroku}}}',
});
```

```ts
resolveText({ key: 'checklist.remaining' }, 'pl', resolver, { n: 3 });
// "3 kroki"
```

A missing category falls back to `other`, then to an empty string — a message
that lacks the category a locale needs degrades instead of throwing.

Directly:

```ts
import { selectPlural } from '@opentutorial/core';

selectPlural(1, { one: '# item', other: '# items' }, 'en');   // '# item'
```

## Button labels

The built-in buttons resolve through the `opentutorial.*` namespace:

```ts
createKeyResolver({
  'opentutorial.next': 'Suivant',
  'opentutorial.back': 'Retour',
  'opentutorial.done': 'Terminé',
  'opentutorial.skip': 'Passer la visite',
});
```

Defaults are `Next`, `Back`, `Done`, `Skip tour` (`DEFAULT_LABELS`).

Per-step overrides bypass the resolver entirely:

```jsonc
{ "buttons": { "next": "Got it", "back": false } }
```

`false` hides a button.

## Right-to-left

```ts
createTutorialLayer({ specs, dir: 'rtl' });
```

The stylesheet uses logical properties, and placements are mirrored — a `left`
placement becomes `right`. One spec serves both directions.

Derive it from the locale:

```ts
import { localeDirection } from '@opentutorial/core';

createTutorialLayer({ specs, locale, dir: localeDirection(locale) });
```

`localeDirection` uses `Intl.Locale` text info where available and falls back to
a language table (`ar`, `he`, `fa`, `ur`, `ps`, `sd`, `ug`, `yi`, `dv`, `ckb`).

Swipe gestures follow reading order too: under RTL, a swipe to the right
advances.

## Per-locale specs

For copy that differs structurally rather than by translation:

```ts
import { extendSpec } from '@opentutorial/core';

const specs = [
  base,
  extendSpec(base, { id: 'welcome-ja', title: { key: 'tour.welcome.ja.title' } }),
];
```

## Checking coverage

`resolveText` returns the key when nothing resolves, so a quick sweep finds gaps:

```ts
import { resolveText, blocksToText, normalizeContent } from '@opentutorial/core';

function missingKeys(spec: TutorialSpec, locale: string, resolver: I18nResolver) {
  const out: string[] = [];
  const check = (content: I18nContent | undefined) => {
    if (content && typeof content === 'object' && 'key' in content) {
      if (resolver(content.key, locale) === undefined) out.push(content.key);
    }
  };

  check(spec.title);
  check(spec.description);
  for (const step of spec.steps) {
    check(step.title);
    for (const block of normalizeContent(step.content, (c) => String(c))) {
      if (block.type === 'text') check(block.value);
    }
  }
  return out;
}
```
